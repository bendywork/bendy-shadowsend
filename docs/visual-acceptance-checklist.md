# 视觉验收清单与截图基线（双主题 × 三断点）

> 需求：REQ-202610-0509 / ui-46「视觉验收清单与截图基线」
> 适用版本：v0.1.69 起
> 依据：`docs/development-plan-2026-10-13-roadmap.md` §3.2、dc-02（纯黑白灰 + 反色主按钮）、dc-04（手机 / 平板 / 桌面全适配）、ui-48（多平台真机与移动端性能）
> 配套工具：`npm run visual:audit`、`npm run visual:baseline`
> 基线目录：`docs/visual-baseline/`（规则见该目录 `README.md`）

本清单是 UI 改版的统一视觉验收口径。每次涉及页面、组件、主题、断点或设计令牌的变更，都按本清单执行；截图基线用于回答「这次改动到底改了什么、有没有误伤」。

## 1. 使用方式（TL;DR）

1. **静态纪律检查**：`npm run visual:audit`，必须 0 violation。
2. **生成截图**：在发布候选（production build）上运行 `npm run visual:baseline -- --base-url <地址> --version <版本>`，产物落到 `docs/visual-baseline/<版本>/`。
3. **人工验收**：按 §5（双主题）、§6（三断点）、§7（全平台矩阵）逐项检查，至少覆盖 §4 的页面与状态。
4. **记录结论**：用 §12 模板记录通过 / 阻塞项；截图、manifest 与缺陷单一起归档。
5. **合并门禁**：P0 未清零不得合并；截图基线未经评审不得覆盖。

> 本清单描述的是 UI 批次（ui-38 / ui-39 / ui-40 / ui-43 / ui-44 / ui-45 / ui-47 / ui-48 等）合并后的目标形态。单独检出某个需求分支时，未合入的页面/抽屉可能尚不存在，按「N/A（依赖未合并）」记录，不得据此判失败。

## 2. 验收环境与前置条件

- 使用 **production build**（`npm run build && npm start`），不使用 dev server 的 HMR 状态做最终判定。
- 固定数据：至少 1 个房主账号、1 个普通成员、1 个待审批用户；房间内包含文本、图片、文件、混合消息各 1 条；公告含 1 张图片；广告位至少 2 条。
- 固定语言：默认 `zh-CN`；另抽测 `en` 一轮（文案溢出、截断与换行）。
- 固定主题：深色（默认）与浅色各跑一遍；切换后刷新验证持久化。
- 浏览器缩放 100%；系统字体使用默认值；关闭浏览器翻译与扩展。
- 记录执行环境：OS、浏览器与版本、设备型号、DPR、时区、执行人、构建版本与 commit。
- 截图与录屏不得包含真实用户隐私数据；使用演示房间与演示昵称。

## 3. 主题与断点矩阵

### 3.1 主题

| 主题 | 入口 | 存储键 | 验收要求 |
| --- | --- | --- | --- |
| 深色 `dark` | 默认 | `localStorage["tb:theme"]="dark"` | 画布 `#08080a`，主按钮白底黑字 |
| 浅色 `light` | 设置/主题按钮 | `localStorage["tb:theme"]="light"` | 画布 `#f4f4f6`，主按钮黑底白字 |

两套主题必须共用同一套语义令牌；浅色只允许覆盖 `--ds-*`，不得出现逐组件反色、`!important` 或 `.bg-*` / `.text-*` 工具类覆写。

### 3.2 断点与代表视口

| 模式 | 宽度 | 布局契约 | 必测视口（CSS px） |
| --- | --- | --- | --- |
| mobile | `< 768px` | 单栏 + 房间/成员双抽屉 | 360×800、390×844、430×932 |
| tablet | `768–1279px` | 两栏（房间栏 + 聊天）+ 成员抽屉 | 768×1024、834×1194、1024×1366 |
| desktop | `>= 1280px` | 三栏（房间 / 聊天 / 成员），左右栏可折叠 | 1280×800、1440×900、1920×1080 |

边界值必须单独验证：**767 / 768 / 1279 / 1280px**。任何视口都不得出现横向滚动（`document.documentElement.scrollWidth === clientWidth`）。

## 5. 双主题验收（dc-02 / ui-38）

### 5.1 黑白灰色彩纪律

**允许的彩色只有语义状态色**：`--ds-success`、`--ds-warning`、`--ds-danger` 及其 `soft / border / glow` 派生值。其余所有颜色必须来自中性灰 ramp 或语义表面 / 文字 / 边框 / 动作令牌。

| 检查项 | 判定标准 |
| --- | --- |
| 旧强调色 | 全站不得出现 `#0a84ff`、`#0071e3`、`rgb(10,132,255)`、`rgb(0,113,227)` |
| Tailwind 彩色工具类 | 不得出现 `bg-blue-*`、`text-red-*`、`border-emerald-*` 等调色板工具类 |
| 硬编码颜色 | 组件（`src/**/*.tsx`）不得硬编码 hex / rgb；需要新颜色时先加 `--ds-*` 令牌 |
| 浅色主题块 | `:root[data-theme="light"]` 内只允许 `--ds-*` 声明与 `color-scheme` |
| `!important` | `globals.css` 不得出现 `!important`（`prefers-reduced-motion` 安全网也走令牌折叠） |
| 主按钮反色 | 深色：浅底深字；浅色：深底浅字；两主题对比度均 ≥ 4.5:1 |
| 广告位 | 忽略广告数据的 `color` 字段，统一继承 `--ds-ink-muted`，hover/focus 提升到 `--ds-ink` |
| 头像 | 9 种头像底色均为灰阶；首字母前景按亮度选择，对比度 ≥ 4.5:1 |
| 二维码 | 固定白底黑码（`--ds-qr-surface` / `--ds-qr-dark`），不随主题反色，对比度 ≥ 7:1 |
| 状态色 | 仅用于成功 / 警告 / 危险语义；不得用于装饰、强调或品牌色 |

自动化：`npm run visual:audit` 会扫描上述规则（含主按钮反色与二维码对比度）。人工：在深/浅两套截图中抽样取色，除状态色外不得出现彩色像素。

### 5.2 主题逐项检查

- [ ] 右上角主题入口可切换深/浅；刷新后保持；首帧无闪白 / 闪黑。
- [ ] `html[data-theme]` 与 `color-scheme` 同步；原生控件、滚动条、表单自动适配。
- [ ] 画布 / 面板 / 卡片 / 浮层四层表面层级可辨，但不依赖重描边。
- [ ] 主文字、次级文字、辅助文字、最弱文字对各自背景 ≥ 4.5:1；大字号 ≥ 3:1。
- [ ] 输入框、按钮、分隔线边界 ≥ 3:1；`:focus-visible` 焦点环 ≥ 3:1 且清晰可见。
- [ ] 成功 / 警告 / 危险提示的文字与 soft 背景对比度 ≥ 4.5:1。
- [ ] 禁用态、hover、active、selected 状态在两种主题下均可区分。
- [ ] 二维码弹窗白底黑码，手机相机可识别；关闭按钮可键盘聚焦。
- [ ] 头像首字母在浅灰 / 深灰底色上均清晰。
- [ ] 图片、Logo、空态插画在浅色下没有残留的深色底或白色描边。
- [ ] 系统开启「减少动态效果」时，主题切换、弹层、Toast、轮播均无位移动画。

## 6. 三断点验收（ui-39 / ui-47）

### 6.1 mobile（< 768px）

- [ ] 360 / 390 / 430px 均无横向滚动；长房名、长昵称、长广告文本正确截断。
- [ ] 房间栏与成员栏以抽屉呈现；遮罩点击、Esc、关闭按钮均可关闭。
- [ ] 抽屉打开时背景滚动锁定；关闭后焦点回到触发按钮；Tab 不逃逸。
- [ ] 抽屉宽度为 `min(88vw, 340/360px)`；左右方向正确；安全区（刘海 / 底部 Home 条）无遮挡。
- [ ] 触控目标 ≥ 44×44px；相邻操作间距足够，不误触。
- [ ] 输入区在软键盘弹出后仍可见；发送按钮不被遮挡；Enter / Shift+Enter 行为正确。
- [ ] 顶栏在窄屏下不溢出；广告位换行到标题行末尾且仍为单行截断。
- [ ] Toast 不超出视口；Modal 在窄屏下占满可用高度并可滚动。

### 6.2 tablet（768–1279px）

- [ ] 768 / 834 / 1024px 均为两栏（房间栏 + 聊天），成员栏以抽屉呈现。
- [ ] 房间栏宽度稳定（约 280px），聊天区 `minmax(0,1fr)` 不被内容撑破。
- [ ] 成员抽屉打开 / 关闭、焦点圈定、滚动锁定与 mobile 一致。
- [ ] 横竖屏切换后布局与抽屉状态正确；无内容跳变或横向溢出。
- [ ] 触控目标 ≥ 44×44px；悬停态不是唯一反馈。

### 6.3 desktop（>= 1280px）

- [ ] 1280 / 1440 / 1920px 均为三栏；左右栏可独立折叠 / 展开。
- [ ] 网格宽度符合 `290px minmax(0,1fr) 290px`（折叠时对应列收起），无横向溢出。
- [ ] 折叠按钮仅桌面显示；折叠状态刷新后保持。
- [ ] 房间列表、消息区、成员列表各自滚动，滚动条样式统一且不挤压内容。
- [ ] 悬停、聚焦、选中、拖拽（如有）状态完整；键盘可达。
- [ ] 超宽屏（1920px）内容不被无限拉伸；阅读行长合理。

### 7.2 移动端性能基线

在低端 Android 或 Lighthouse 移动模拟（Slow 4G、CPU 4×）下，对 `/` 与 `/room/:roomCode` 各跑 3 次取中位数：

| 指标 | 良好阈值 | 记录字段 |
| --- | --- | --- |
| LCP | ≤ 2.5s | 首屏最大内容绘制 |
| CLS | ≤ 0.1 | 布局偏移 |
| INP | ≤ 200ms | 交互响应 |
| TTFB | ≤ 800ms | 服务端响应 |
| 首屏 JS（gzip） | 记录并对比上一基线 | 不得无理由增长 > 10% |
| 长任务 | 首屏无 > 200ms 长任务 | Performance 面板 |

性能基线随版本记录；超过阈值或较上一基线回退 > 20% 时，需在验收记录中说明原因并由负责人签字。

## 8. 截图基线

### 8.1 基线集合

每个版本至少采集 **3 个页面 × 2 个主题 × 3 个代表视口 = 18 张**：

| 页面 | 路由 | 视口 |
| --- | --- | --- |
| 首页 | `/` | 390×844、834×1194、1440×900 |
| 房间页 | `/room/:roomCode` | 390×844、834×1194、1440×900 |
| 404 | 任意不存在路由 | 390×844、834×1194、1440×900 |

发布候选可扩展到 §3.2 的全部 9 个视口（54 张）。扩展集不替代基础集。

### 8.2 命名与目录

```text
docs/visual-baseline/
├── README.md
├── manifest.template.json        # manifest 字段空模板
└── <version>/
    ├── home--dark--1440x900.png
    ├── home--light--1440x900.png
    ├── room--dark--390x844.png
    ├── ...
    └── manifest.json             # 该版本基线的索引（环境、哈希）
```

命名规则：`<page>--<theme>--<width>x<height>.png`，全小写、连字符分隔；`page` 取 `home` / `room` / `not-found`。文件名不得包含空格、斜杠、中文或 `..`。

### 8.3 采集环境

- 浏览器：Chromium（版本写入 manifest）；`deviceScaleFactor=1`；`locale=zh-CN`；`timezone=Asia/Shanghai`。
- 动效：`prefers-reduced-motion: reduce`，避免动画帧差异。
- 数据：使用固定演示数据（mock 或 seed），消息时间、昵称、房间号固定；不得使用真实用户数据。
- 主题：通过 `localStorage["tb:theme"]` 预设，刷新后截图；每张图记录实际 `data-theme`。
- 等待：`main` 可见 + 字体加载完成 + 700ms 稳定期；二维码等异步内容需等待其出现（404 页以 `body` 为锚点）。
- 截图范围：默认视口截图；长页面可加 `--full-page`，但同一版本内保持一致。

### 8.4 采集命令

```bash
# 1) 启动生产构建
npm run build
npm start -- -p 3000

# 2) 另开终端采集（mock 数据，默认 18 张）
npm run visual:baseline -- --base-url http://127.0.0.1:3000 --version 0.1.69

# 3) 扩展视口 / 指定输出目录
npm run visual:baseline -- --base-url http://127.0.0.1:3000 \
  --version 0.1.69 --viewports mobile-360,mobile-390,mobile-430,tablet-768,tablet-834,tablet-1024,desktop-1280,desktop-1440,desktop-1920
```

工具会写出 `<version>/manifest.json`，包含每张图的 `sha256`、字节数、浏览器版本、视口、主题与采集时间。若本机没有 Playwright，按提示安装 `playwright-core` 并设置 `CHROMIUM_PATH` 指向 Chromium / Chrome 可执行文件。

### 8.5 基线的评审与更新

1. **只在有意变更时更新**：UI 改版、令牌调整、文案布局变化才允许刷新基线；重构但视觉不变时不得覆盖。
2. **先看 diff 再提交**：用图片 diff 工具（如 `npx pixelmatch`、ImageMagick `compare`）对比新旧图；每张变化图都要说明原因。
3. **保留旧版本**：至少保留上一个发布版本的基线目录；不要在原目录上原地覆盖。
4. **PR 必带**：`manifest.json` diff、变化截图、变化原因、受影响页面清单。
5. **评审人**：至少 1 名非作者确认「变化符合预期、无彩色强调残留、无布局回归」。
6. **不提交**：真实用户数据、含敏感信息的房间、带个人令牌的 URL、超过 5MB 的单张图片。

## 9. 黑白灰自动审计

`npm run visual:audit` 检查：

- `src/**/*.tsx` 中不得出现 Tailwind 彩色工具类与硬编码彩色 hex / rgb。
- 全仓不得出现旧强调色 `#0a84ff` / `#0071e3` 及其 rgb 形式。
- `globals.css` 不得出现 `!important`；浅色主题块只允许 `--ds-*`。
- 主按钮令牌必须反色且对比度 ≥ 4.5:1。
- 二维码前景 / 背景对比度 ≥ 7:1。
- 头像色池必须为灰阶。

审计失败时输出文件、行号、规则与修复建议；CI/本地均以退出码 1 阻断。

## 11. 缺陷分级与通过标准

| 级别 | 定义 | 示例 | 处理 |
| --- | --- | --- | --- |
| P0 阻塞 | 核心流程不可用、内容不可读、主题/布局严重破坏 | 横向滚动、文字 < 4.5:1、抽屉无法关闭、二维码不可识别、残留蓝色强调 | 修复后重跑全矩阵 |
| P1 严重 | 明显视觉回归或可访问性缺陷，但有绕过方式 | 焦点环缺失、触控目标 < 44px、状态色对比不足、错位 | 合并前修复 |
| P2 一般 | 细节不一致，不影响使用 | 间距偏差 4px、图标线宽不一致、截断位置不理想 | 可排期修复 |

**通过标准**：P0 = 0、P1 = 0、P2 有明确排期；`visual:audit` 0 violation；基础截图集齐全且 manifest 校验通过；真机矩阵中 P0 平台全部 PASS。
