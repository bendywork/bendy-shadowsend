# 房间设置抽屉（Room Settings Drawer）

> 适用版本：v0.1.69（REQ-202610-0488 / ui-13）

## 1. 背景与目标

v0.1.58 的房间设置是右侧栏内的窄 Popover：名称、门禁码、加入策略、过期策略挤在四个同权重小卡片里，缺少层级、说明和危险操作入口；解散房间则单独放在 Header 的垃圾桶图标上，容易误触且与设置上下文割裂。

本迭代将设置重构为独立贴边抽屉，目标是：

- 用固定的信息架构承载全部房主设置：**名称 / 门禁码 / 加入策略 / 过期 / 危险区**。
- 每个区域都有标题、编号、说明和明确的操作反馈，避免“只有控件没有解释”。
- 把不可逆的解散操作收进抽屉危险区，使用内联二次确认替代 `window.confirm`。
- 保持与现有设计系统一致的语义 token、焦点管理和动效约束。

## 2. 信息架构

抽屉从上到下固定为：

| 顺序 | 区域 | 内容 | 风险级别 |
| --- | --- | --- | --- |
| — | 房间概览 | 房间号、房主、成员数/在线数 | 只读 |
| 01 | 房间名称 | 名称输入、字数计数、保存 | 低 |
| 02 | 门禁码 | 6 位数字输入、保存、清除、当前值 | 低 |
| 03 | 加入策略 | 允许申请加入开关 + 状态 | 中 |
| 04 | 过期策略 | 永不过期开关 + 状态 | 中 |
| 05 | 危险区 | 解散房间 + 内联确认 | 不可逆 |

顺序遵循“只读 → 低风险编辑 → 策略 → 不可逆操作”，危险区永远最后出现。`ROOM_SETTINGS_SECTION_ORDER`（`src/lib/room-settings.ts`）固定该顺序并由单测保护。

## 3. 视觉规范

### 3.1 抽屉容器

- 复用 `Popover` 的 `variant="drawer"`：`Drawer` 是薄包装，保留 portal、滚动锁定、焦点陷阱、Esc/遮罩关闭与焦点归还。
- 默认右侧贴边，`size="lg"`（`max-w-lg`），高度 `100dvh`，仅左侧描边，无圆角。
- 入场只改变 `transform` 与 `opacity`（`drawer-in-right`）；`prefers-reduced-motion` 下关闭动画。

### 3.2 概览条

- 三列 `dl`，用细分隔线形成“账本条”，不使用通用卡片网格。
- 标签为 10px 大写字母 + `0.12em` 字距；房间号使用等宽字体。
- 窄屏（≤520px）折叠为单列，分隔线改为横向。

### 3.3 分区与节奏

- 每个分区使用 `01`–`05` 等宽编号作为左侧导轨，正文与标题共用一条对齐轴（`2.25rem + gap`）。
- 分区之间用 `--ds-line-subtle` 顶部分隔线，垂直节奏为 `--ds-space-5` / `--ds-space-6`。
- 标题 14px/600，说明 12px/1.55；字段标签 10px 大写，形成三级层次。

### 3.4 字段与开关

- 输入框复用 `.field`，高度 36px，聚焦走全局 focus ring；错误态使用 `aria-invalid` + `.field-error`。
- 门禁码输入使用等宽字体与 `0.28em` 字距，强化“6 位数字”的感知。
- 开关复用 `src/components/ui/switch.tsx`：`role="switch"`、`aria-checked`、`aria-labelledby`，支持禁用、hover 与 focus-visible。
- 开关行使用弱背景 + 细描边，状态文案（允许/拒绝、已开启/已关闭）在开关左侧，开启时使用 `--ds-success` 语义色。

### 3.5 危险区

- 使用 `--ds-danger-soft` 背景与 `--ds-danger-border` 描边，编号同样使用 danger 色，形成明确的终止感。
- 默认只显示“解散房间”按钮；点击后原地展开确认块（`role="alert"`），包含房间名与“确认解散 / 取消”。
- 确认块出现后不再提供其他危险操作，避免连续误触。

## 4. 交互契约

- **脏状态保存**：名称与门禁码只有与当前值不同才可保存；名称比较忽略首尾空白。
- **门禁码清除**：`清除` 直接以空值调用保存接口，不依赖异步 state；无门禁码时禁用。
- **输入同步**：抽屉打开期间，快照轮询不覆盖正在编辑的输入；关闭后与最新快照重新对齐。
- **保存反馈**：按钮进入 `保存中…` 并显示 spinner，成功后 Toast，失败走 `toastError`。
- **关闭**：右上角关闭按钮、底部“完成”、Esc、点击遮罩均可关闭；关闭后焦点回到触发按钮。
- **解散**：仅在抽屉内二次确认后调用；成功后按现有逻辑跳转到下一个房间或首页。

## 5. 无障碍

- `Drawer` 输出 `role="dialog"`、`aria-modal="true"`、`aria-labelledby` / `aria-describedby`。
- 分区使用 `<section aria-labelledby>`，概览使用 `<dl>`，危险确认使用 `role="alert"`。
- 所有输入都有显式 `<label>`；错误通过 `aria-invalid` + `aria-describedby` 关联。
- 开关通过 `aria-labelledby` 关联可见标题，状态文案不单独依赖颜色。
- 全局 `:focus-visible` 样式覆盖按钮、输入与开关；动画只使用 `transform` / `opacity`。

## 6. 测试与验收

单测：

- `src/lib/room-settings.test.ts`：分区顺序、名称截断、门禁码清洗、脏状态、门禁码存在性。
- `src/components/chat/room-settings-drawer.test.tsx`：五个分区顺序、概览信息、双开关状态、未修改时保存禁用、错误态、清除禁用、保存中状态、危险区默认不展示确认。

- [ ] 房主点击 Header 设置按钮，右侧抽屉打开，五个分区顺序正确。
- [ ] 概览显示房间号、房主、成员数/在线数。
- [ ] 名称与门禁码修改后可保存，未修改时保存按钮禁用；门禁码可清除。
- [ ] 加入策略、过期策略开关即时保存并显示状态。
- [ ] 解散房间需在危险区内二次确认，取消可收起确认。
- [ ] 抽屉打开时轮询不会覆盖正在编辑的输入。
- [ ] 键盘 Tab 被圈定在抽屉内，Esc 关闭并归还焦点。
