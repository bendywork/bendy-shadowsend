# 消息滚动与历史分页规范

> 适用版本：v0.1.69（REQ-202610-0493 / ui-30）
> 目标：新消息自动定位、阅读历史时保持滚动锚定、向上翻页加载平滑，且不打断用户阅读。

## 1. 行为约定

| 场景 | 行为 |
| --- | --- |
| 首次进入房间 | 无动画定位到最新一条消息 |
| 停留在底部（距底 ≤ 96px） | 新消息到达时平滑滚到底部，不显示未读提示 |
| 正在阅读历史（距底 > 96px） | 保持当前视口位置，显示「N 条新消息」浮动按钮与「以下为新消息」分隔线 |
| 自己发送消息 | 无论当前滚动位置，自动回到最新消息 |
| 滚动到顶部（距顶 ≤ 120px） | 自动请求上一页（`before` 游标），加载前记录首个可见消息，加载后按锚点恢复位置 |
| 内容不足一屏 | 自动补拉历史，直到填满视口或没有更多 |
| 历史加载失败 | 顶部显示行内错误 + 「重试」，同时走统一 Toast；不静默失败 |
| 历史加载完毕 | 顶部显示「已显示全部消息」 |

## 2. 实现结构

- `src/lib/message-scroll.ts`：纯函数与常量（阈值、距离计算、分页判断、消息合并、新消息后缀检测、锚点偏移）。
- `src/components/chat/use-message-scroll.ts`：滚动状态机；管理 `scrollRef` / `contentRef`、锚点、未读数、首次定位、`ResizeObserver` 与顶部触底加载。
- `src/app/room/[roomCode]/page.tsx`：历史分页请求、快照合并、消息节点 `data-message-id` 标记与 UI 呈现。

关键常量：

| 常量 | 值 | 用途 |
| --- | --- | --- |
| `MESSAGE_BOTTOM_THRESHOLD_PX` | 96 | 判定「停留在最新消息」 |
| `MESSAGE_HISTORY_THRESHOLD_PX` | 120 | 判定「接近顶部」 |
| `MAX_MESSAGES_IN_MEMORY` | 600 | 停留在底部时的内存消息上限，避免无限增长 |
| `MESSAGE_PAGE_SIZE` | 120 | 服务端分页大小 |

## 3. 锚定与分页细节

- 每条消息（含本地待发送消息）渲染为带 `data-message-id` 的节点；锚点记录第一个与视口相交节点的 `id` 与 `getBoundingClientRect().top`。
- DOM 变化后用 `nextScrollTopForAnchor` 修正 `scrollTop`，图片加载、消息展开等高度变化由 `ResizeObserver` 兜底。
- 历史前插不会触发未读计数：只统计「上一批最新消息之后新增、且发送者不是自己」的消息。
- 快照同步（15s）与历史页按 `id` 去重合并，已加载的历史不会被快照覆盖；快照只在首次初始化时决定 `hasMoreHistory`。
- 平滑滚动遵循 `prefers-reduced-motion: reduce`，降级为瞬时滚动。
- 新消息提示使用 `aria-live="polite"`，分隔线带 `role="separator"`，浮动按钮可通过键盘聚焦。

## 4. 验收清单

- [ ] 进入房间直接看到最新消息，无跳动。
- [ ] 向上阅读时收到新消息，视口不移动，浮动按钮计数正确。
- [ ] 点击浮动按钮回到最新，分隔线与计数清除。
- [ ] 滚到顶部自动加载上一页，加载前后第一条可见消息位置不跳变。
- [ ] 图片加载完成或消息展开后，阅读位置保持稳定。
- [ ] 历史加载失败可重试，且失败只提示一次。
- [ ] `npm test`、`npm run lint`、`npx tsc --noEmit`、`npm run build` 全部通过。
